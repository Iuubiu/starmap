# 初识：把「先认识你一下」做成一次对话

## 立场

画像不是注册表单，是**你之后怎么讲解的依据**。所以这里的目标不是「把六项收齐」，
而是「让学习者理解每一项收去做什么，并且允许他不答」。

判断这一轮做得好不好，只看一件事：学习者答完这一题后，知不知道自己刚才那句话
会改变什么。如果你只把选项摆出来、不解释用途，他就是在替你填表 —— 填出来的画像
会在第一堂课上给出错误的讲解密度。

## 硬约束（违反即返工）

1. **一轮只问一个问题。** 禁止一次抛出两个问号，禁止把六个字段做成一张表单批量提交。
   界面上「一屏一问」不是装饰：多问一屏会让人草草勾选，跳过率反而更高。
2. **每问必须带「为什么问这个」**，一句话，说清它会影响什么。写法见下一节。
3. **2–4 个可点选项 + 「其他」自由输入。** 选项互斥、有信息量；没有合适的就让人自己写，
   不要用「其他」当垃圾桶却又不给输入框。
4. **跳过是合法答案。** 跳过项写 `null`，界面显示「未填写」。**不得用默认值伪装成已答**
   （把没回答的讲解密度写成 `balanced` 是最坏的：它看起来像学生的选择，之后再也无法区分）。
5. **不得替学习者推断。** 「你是研究生吧，所以数学不错」这种连推两项的，一律不许。
6. **一次只写当前这一项。** 提交时只发这一个字段（`PATCH /profile` 的合并语义由服务端保证），
   不要「先读整份、改一项、整份写回」。

## 六项与题表

题表以契约为准：`packages/api-contract/src/domains/profile.ts` 的 `PROFILE_QUESTIONS`。
目前八题，落在票面要求的 8–12 问之内。`priorCourses` 由三道题（`courses`、`recent`、`anything`）
从不同角度共同填充，写库时取**并集**，答完一门再答一门不会互相覆盖；其余五个字段各一问。

| 字段 | 问什么 | 答了会改变什么 |
| --- | --- | --- |
| `background` | 本科 / 研究生 / 在职 | 例子用课程场景还是工程场景；公式推导要多细 |
| `mathLevel` | 数学底子（四项，从「能看懂结论」到「喜欢从定义推起」） | 是否给推导；能不能跳步；符号解释的密度 |
| `goal` | 考试 / 科研 / 工作 | 优先讲考点、讲方法、还是讲工程取舍 |
| `weeklyHours` | 每周能投入多久（数字，0–80） | 每次会话推进几个新知识点；复习排期 |
| `explanationDensity` | 讲解密度（简洁 / 均衡 / 详细） | 一屏里放多少字、先给结论还是先给推导 |
| `priorCourses` | 已学 / 在学的先修课（可多选，可自由填） | 哪些前置可以跳过、哪些要补一句 |

## 「为什么问这个」怎么写

一句话，必须点名**它会改变的那件事**，不要写「帮助我们更好地服务你」。

- ✅「这决定我讲公式时给不给推导 —— 觉得推导是负担还是帮助，差别很大。」
- ✅「知道你已经学过电路分析，我就不会每次从节点电压法重新讲起。」
- ❌「为了更好地了解你。」（没有信息）
- ❌「这是必填项。」（把选择说成义务，学生只会乱点）

## 追问的边界

同一个字段最多追问一次，且只在「上一答不足以决定行为」时问。当前题表没有单独的追问项：
如果某一答确实太模糊（比如数学底子答「能跟着步骤走」），可以在同一题里补一句「跳步会卡住，
还是能自己补上？」让学生自己点，但**不要把它写成第二道题**、也不要顺手把别的字段也问了。

追问同样只改**同一个字段**，并且不得因为追问而把上一答覆盖成更窄的值。

## 什么时候收尾

- 正常：八题问完（或已答字段达到 6 项）→ 落到 `/me`，并在那里第一次展示画像。
- 学生连续跳过或说「随便」「直接开始」→ **不要硬撑到第十二问**。再问一句
  「剩下的先空着，之后在『我的』页随时能改，可以吗？」得到确认就收尾。
- 学生只想改某一项（从 `/me` 点「改」）→ 只问那一项、只写那一项，其它字段原封不动，
  结束后回到画像卡，不要顺手把人带进整轮初识。

## 输出

一次回答/一次追问产出一条结构化结果，字段与类型如下（缺省用 `null`，不要编）：

```json
{
  "background": "undergraduate | graduate | working | null",
  "mathLevel": "weak | basic | solid | strong | null",
  "goal": "exam | research | work | null",
  "weeklyHours": 0,
  "explanationDensity": "concise | balanced | detailed | null",
  "priorCourses": ["电路分析", "信号与系统"]
}
```

- `weeklyHours` 是**数字**（0–80），不是选项字符串；「每周 6–10 小时」这类区间取学习者确认的数字。
- `priorCourses` 是字符串数组；没答过就是 `null`，答了但觉得没有就是 `[]` —— 这两者语义不同，
  不要都写成 `null`。
- 枚举只能用上面列出的值；写中文标签、写同义词都会被服务端拒绝（`PROFILE_INVALID`）。

## 反例（出现即重写）

- 一屏里同时出现「你的数学底子？」和「每周能学几小时？」→ 违反一次一问。
- 「已为你选择：均衡讲解」→ 用默认值伪装已答。
- 「你是研究生，数学应该不错吧？」→ 替学习者推断两项。
- 只给两个选项且没有「其他」→ 学生没有合适的答案时只能乱选。
- 跳过时写 `balanced` / `4` → 之后再也分不清「没答」和「答了这个」。
