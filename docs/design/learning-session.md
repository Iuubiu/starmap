# 学习会话 · 产品设计说明

> 读者：产品、投资人、教学方

---

## 1. 这台工作站在做什么

StarMap 是一个**个人学习工作站**：它不按章节从头讲课，而是先弄清楚「你现在卡在哪」，再给一张能立刻上手的卡片。

学习者只需要说一句话，比如「明天考数电，布尔代数是必考」。系统接下来做的事是：

1. **问两三个问题**确认基线（学过没有、是为了考试还是为了懂）；
2. **定一条路线**（从第几段开始讲、讲多细）；
3. **带着练**：边讲边出题，错的当场指出错在哪一步；
4. **给结论**：这一关过了没有、掌握度变成多少、下次什么时候再来复习。

整个过程学习者只做两件事：**说话**，或**点卡片上的选项**。没有菜单要背，没有章节要选。

## 2. 三种人，同一套流程

| 谁 | 他会怎么说 | 系统怎么应对 |
|---|---|---|
| **完全没学过** | 「我完全没学过，从哪开始」 | 先给一个完整例子走一遍，再让他自己动手；一轮只推 2 个新知识点，不贪多 |
| **学过但卡住** | 「我会一点，但一化简就乱」 | 不讲整章，只把他卡住的那一步挑出来问，让他自己补上；一轮推 3 个 |
| **考前突击** | 「明天就考，只想练最容易错的」 | 跳过讲解直接进练习，错的地方指到具体一项；一轮推 4 个 |

三个人进的是**同一个知识点**，用的也是**同一套判据**——差别只在起点和节奏。这点很重要：系统不给人贴标签，它只调整「从哪儿开始、讲多细」。

## 3. 功能清单

### 3.1 学会一件事的完整链路

| 功能 | 解决什么 | 学习者看到什么 |
|---|---|---|
| **开口即开始** | 不用先选章节 | 说一句话，系统就开始问 |
| **基线确认** | 避免「你觉得你什么水平」这种无效提问 | 两三个具体问题（你手边有什么数据？你是为了考试还是为了懂？） |
| **路线与节奏** | 不同人不用同一条路 | 一张关卡卡：几分钟、几道题、从哪一段开始 |
| **七段教学** | 讲—练—判分离，不会「讲完就完」 | 引导 → 例子 → 简单题 → 深究 → 再讲 → 判定 → 小结 |
| **错题修正** | 错了不能只对答案 | 先判断「是概念混了还是算错了」，再只问一个关键点，让学习者自己说出来 |
| **通关结论** | 让人知道「到底过没过」 | 三条标准全部满足才算过，附掌握度变化与下次复习时间 |

### 3.2 让人相信自己被「看见」的三个东西

1. **每一轮都有据可查**：右栏写着这一轮检索到几段教材、放行了哪几段、调用了哪几个技能、判定成了什么。学习者可以点开看依据。
2. **掌握度不是感觉**：它是一个数字，随作答上涨，答错只影响「当前熟练度」，历史最高不会被抹掉。
3. **下次什么时候回来**：通关时直接告诉你「1 天后我会来找你」，之后按 1 / 3 / 7 / 21 / 60 天自动安排复验，不用自己记。

### 3.3 九个页面，一条主线

学习页是入口，其余八页是「查证」用的：

| 页面 | 用来干什么 |
|---|---|
| 学习 | 对话与闯关（主战场） |
| 定级 | 用几道题测出当前档位 |
| 复验 | 到期该复习的知识点排队 |
| 看板 | 今天学什么、为什么是它 |
| 知识地图 | 看一个知识点前后左右都连着谁 |
| 关卡市场 | 挑一关练，或把自己学的存成关卡 |
| 数据库 | 每个知识点出自哪本书、第几页 |
| 内容库 | 库里有哪些教材、题库、技能 |
| 技能库 | 系统会哪几种教法，各在什么场景用 |

## 4. 一轮对话怎么进行（人机交互）

这是整个产品最核心的循环，一次大约十几秒：

```
学习者说一句话
   ↓
系统先「想」——把这一轮要确认的事想清楚（约 2 秒，边想边把思路显示出来）
   ↓
系统回答，并给出下一张卡片
   ↓
学习者二选一：点卡片上的选项，或直接在输入框说一句
   ↓
系统先确认「我记下了」，再进入下一轮
```

三个刻意的设计：

- **先想再答**：思考过程要在回答**之前**出现。顺序反了，用户会认为答案是先编好的。
- **两条回答通道**：有的人愿意点，有的人想解释自己的思路。两条路都能推进，系统都会回一句「记下了：你选的是…／你写的是…」，让人确认被听见。
- **一次只问一个问题**：追问不超过两句。层层追问是为了让学习者自己跨过那一步，不是为了考倒他。

## 5. 「算不算学会」怎么判

不设「答对 80% 就过关」这种粗暴阈值，而是三条同时满足：

| 门槛 | 意思 | 为什么 |
|---|---|---|
| **至少 8 道题** | 题太少，对错都说明不了什么 | 防止运气好一次通关 |
| **覆盖 3 个变式** | 同一个知识点换三种问法 | 防止只会背这一道 |
| **连续答对 2 次** | 中间不夹错 | 防止「蒙对一次」 |

错题不进判定池，但会进复验队列——**错过的题一定会再来找你**。这也是为什么通关卡上写的是「错的那两题已进复验队列」，而不是简单扣分。

复验按 1 / 3 / 7 / 21 / 60 天阶梯推进：答对往上走一层，答错往回退一层，但**历史最高掌握度永不下降**。这条规则是为了让人敢答错。

## 6. 效果

### 6.1 一次典型会话（考前突击型）

| 阶段 | 发生了什么 |
|---|---|
| 开口 | 学习者：「我想学能量分辨率，实验室那台 HPGe 的峰看着比别处胖」 |
| 基线 | 系统问两个问题：你手边能拿到什么数据？你更想先搞公式还是先看谱？ |
| 定线 | 给定一条：从「峰形为什么变宽」入手，4 题、14 分钟 |
| 教学 | 七段推进，两处错题被当场诊断（把「+」当成「·」、把 FWHM 变宽当成分辨率变差） |
| 通关 | 掌握度 66% → 84%，三条门槛全满足，1 天后自动安排复验 |

### 6.2 可观测的结果

- **一轮十几秒**，学习者不需要等几十秒才看到反馈；
- **通关判定可解释**：三条门槛各自的进度在右栏实时可见，不是最后弹一个分数；
- **九页随时可切**，回来对话还接着走，不会丢进度；
- **每个数字都能查**：掌握度、题数、变式数、连对数，右栏都指得出是哪条证据。

## 7. 产品规则（几条不妥协的）

1. **档位不能自选**。档位是测量结果，想升级只能多做题。
2. **错题要回来**。错过的题一定进复验队列，不因为通关就消失。
3. **历史最高不下降**。答错只影响当前熟练度。
4. **地图不画全图**。三千个知识点一次铺开读不出结构，只看当前知识点前后两跳的关系。
5. **禁用的技能连名字都不出现**。系统不该靠「告诉模型别用」来约束行为，而是根本不把那条指令发出去。
