# 苏格拉底追问循环写在 engine 纯函数里，不用 Mastra Workflow

既然把 Mastra 当框架选了，核心教学循环却放在框架外看起来是自相矛盾。理由是这两种东西的性质不同：Workflow 擅长表达「跑一批批处理任务」，而追问循环是**每个回合停下来等一个学生回答**、由阈值驱动的状态机，它需要被单测穷举每一条分支路径，也需要在阈值改动时不依赖框架升级。

## Consequences

- 追问状态是显式的纯数据（阶段、连续失败计数、当前阶梯级别、最近错误类型），进出 engine 都是值，可以对着表穷举测试。
- Mastra 的 Workflow 只用于离线批处理（批量生成关卡），不用在交互主路径上。
- 代价：suspend/resume、状态持久化、跨回合恢复要自己写，不能白拿框架的 snapshot 能力。这条代价是明知的——换来的是教学策略可以被完全测试。
