# 09: 检索与答案块门控 + 检索调试器

**What to build:** 让「不给答案」成为架构事实而不是提示词请求：检索层按掌握度**物理过滤**掉答案块。并给一个调试器，让这件事可被看见。

**Blocked by:** 02, 08

**Status:** ready-for-agent

- [x] 检索以 BM25 起步（两端点均无 embeddings，向量检索是阶段二）
- [x] 答案块是**按知识点标记**的：`chunk_kp_answer(chunk_id, micro_kp_id)` 关系表；同一个 chunk 对 A 知识点是答案块、对 B 知识点是背景，必须能同时成立
- [x] 三档门控真实生效：`current < 0.4` 只返回对**当前知识点**非答案的块、`0.4–0.7` 返回提示／结构／定义块、`> 0.7` 返回全部含答案块
- [x] 检索调试器能输入一个 query，看到：命中的 chunk、每块对当前知识点是否为答案块、以及**被排除的具体原因**
- [x] 同一个 query 在三个不同 `current` 下返回**不同集合**，且差异恰好等于答案块集合——有测试直接断言这个集合运算
- [x] 有测试覆盖「同一 chunk 在两个知识点下门控结果相反」，防止实现退化成全库布尔
- [x] 门控发生在检索层，不依赖提示词；即使把整段上下文喂给模型，答案块也不在上下文里
