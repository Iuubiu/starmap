# 11: 初始定级

**What to build:** 新用户不该一上来就考 20 题，也不该被当成零基础。用 4 题行为自评 + 8–18 道来自「马上要学的知识点池」的定级题，定出一个临时档位，并允许日后重判。

**Blocked by:** 05, 08

**Status:** ready-for-agent

- [x] 自评只问 4 题、只问行为（最近学过什么／能不能手算某类题），不问「你觉得自己几分」
- [x] 定级题**必须来自用户马上要学的知识点池**，不是通用题库——否则定完级学的内容和定级内容无关
- [x] 三个停止条件都实现：后验标准差 ≤0.35 / 连续 3 题落在 40–70% 带 / 熵变化 <0.01；题量落在 8–18 之间
- [x] 定级结果**必须展示答案与解析**，让用户能判断系统有没有把自己判错
- [x] 定级结果是 `provisional`，学满 3 个知识点后自动重判并可升降级
- [x] 定级过程本身不产生掌握度记录（它不是练习）

## Comments

### 1. 验收 5 的门槛口径：票面写错了，按 spec「学 5 题」实现

票面验收 5 写的是「学满 **3 个知识点**后自动重判」。这与 spec 两处原文冲突：

- `spec.md:52`（用户故事）：「我想定级结果是临时的、**学 5 题后**可以重判，以便系统错了能纠正」
- `spec.md:283`（Implementation Decisions）：「低置信度判为 `provisional`，**学 5 题后**可重判」

「每完成 **3 个知识点**重评」出现在 `spec.md:281`，讲的是**票 12 的流程重评**
（档位渲染参数调整 + 用平均首轮正确率升降级），与票 11 的「定级结果重判」是
两件事。票 11 的票面把票 12 的门槛抄了进来。

**本票按 spec 实现：门槛 = 累计计入掌握度的作答 ≥ 5 题**
（`PLACEMENT_LIMITS.rejudgeAfterAttempts = 5`）。「每完成 3 个知识点重评」不在本票范围。

为什么不保留两个门槛取先到者：一个知识点「学完」需要 `evidenceSufficient`
（8 题 + 3 变式），3 个知识点至少 24 题 —— 5 题门槛永远先到，「3 个知识点」这个
门槛在数学上永远不会起作用。留着它只会得到一条永远不会红的测试和一个进不去的分支。

顺带：`confirmed` 这个状态在票 11 的实现里不可达（没有任何写入路径），已从契约与
engine 类型里删掉 —— 见第 4 条。

### 2. 「自动重判」是服务端惰性结算，不是前端点按钮

票面验收 5 的「自动」有三个候选做法，选了第三种：

1. **定时任务** —— 要为可能永不发生的状态转换养一个调度器，且重判时刻会随进程重启漂移。
2. **写在学习动作里**（`AttemptsService.record` 之后）—— 会把全库掌握度回放塞进每一次
   作答的热路径，而重判是低频事件。
3. **读状态时结算**（选中）—— `GET /api/v1/placement` 发现 `shouldRejudge` 成立就当场
   调用 `applyRejudge()` 并落库，然后返回新的档位与一条 `lastRejudge` 说明。

「自动」的定义因此是**系统行为**：不依赖任何一个客户端的按钮。CLI、文档、将来的移动端
只要读一次状态就拿到同一份结论。幂等靠结算后立刻把 `attempts_baseline` 前移到当前
作答总数，下一次 `since` 归零。手动 `POST /placement/rejudge` 保留给「客户端手里是旧快照」
的情形，两条路径共用同一个 `applyRejudge()`（复制一份升降级规则一定会漂移）。

界面上必须解释这件事：学习者**没点任何按钮、档位却变了**，不说话看起来就是应用出错。
所以 `PlacementStatusResponse.lastRejudge` 会带上「从 P1 调整为 P2」和理由。

### 3. 定级题池不读 `app.mastery` 快照，用 `attempts` 回放

`loadCandidates()` 曾经是 `LEFT JOIN mastery ms ... WHERE ms.state IN ('unseen','attempted')`，
即从**派生缓存**判断「这个知识点是不是已经学完」。本项目规矩是
**canonical = `attempts` 回放**：`app.mastery.current` 会随时间衰减
（`apps/api/src/mastery/mastery.service.ts` 文件头），读列等于把「上次算的时刻」当成「现在」。

这条现在等于没过滤（`app.mastery` 是 0 行或接近 0 行），等有人写入 mastery 之后才开始误判 ——
「明明答过题却还被当没学过」这类错误会在没人记得这里读过快照的时候冒出来。

改为取出全部叶节点题目后，用与掌握度接口同一套 `snapshotOf` 回放淘汰
`evidenceSufficient && achieved >= 0.7` 的知识点。测试 `placement.controller.test.ts`
的「题池不看 `app.mastery` 快照」用三种实现各自的数字把这件事钉住
（回放 = 21 题 / 读快照 = 14 题 / 完全不筛 = 28 题）。

### 4. `confirmed` 是死枚举值，已删

契约里 `status` 曾声明 `none | provisional | confirmed`，但全仓没有任何路径写
`'confirmed'`：`upsertProfile()` 只写 `'provisional'`，`applyRejudge()` 的 UPDATE 根本不碰
`status` 列。留着它，下一个读代码的人会以为存在「已确认档位」这个状态，写一条覆盖它的
测试，或在某处依赖 `status === 'confirmed'` 做分支。

spec 的语义本来就是「定级结果永远是临时的、随时会被学习证据修正」，没有「确认后不再改」
这个终态 —— 硬造出来只会得到「已确认但系统还能改」的矛盾。

### 5. 真实库的题池：10 道题 / 7 个叶知识点

`app.level_items` 里挂在 `is_leaf = true` 知识点上的题共 10 道，分布在 7 个知识点
（`kp-bool` 4 题 + 6 个 `lv-ai-*` 各 1 题）。`minItems = 8`，所以真实库能跑完一次定级，
会走 `no_more_items` 停止、`lowConfidence: true` —— 这是**正确的降级**而不是缺陷：
题池来自「马上要学的知识点」，而语料目前只覆盖了 7 个叶知识点。

`is_leaf = true` 这个过滤不能为「题池太小」放宽：`tools/ingest/toc.py` 明确把
章节附件（小结/习题/附录）的 `isLeaf` 设为 false，一处改动同时达到「不进地图、
不算掌握度、不出题」三个效果。放宽等于把小节习题当可学知识点。

### 6. 为什么不改成「门槛一到就用前 5 题的首轮正确率试探性重判」

这是第 1 条改动留下的一个真实副作用，已评估并**明确决定不改判据**。

**现象**：`averageFirstTryRate` 只在「有知识点 `evidenceSufficient` 且 achieved ≥ 0.7」
时才有样本。所以刚开始学的新人做完 5 题过了门槛，首次重判只会得到
`averageFirstTryRate: null` + 档位不变 —— 票面说的「可升降级」在最初几天实际只
兑现了「不降」这一半。看到这个会说「那就用那 5 题的首轮正确率算啊」，不要这么做：

1. **样本量 5 的首轮正确率，标准误约 0.22。** 这是 `sqrt(p(1-p)/n)` 在
   `p=0.5, n=5` 处的值（`sqrt(0.25/5) = 0.2236`）。用它升降档等于让一个人的档位
   由抛硬币决定 —— 而档位是**每关的渲染参数**，「被误判成 P1」的代价是整个界面
   被降配（完整样例、反馈延迟、尝试次数全都跟着变）。用 5 个二值样本驱动一个
   影响整个学习体验的开关，是把统计噪声放大成产品行为。
2. **spec 的原文是「学 5 题后可以重判」，不是「5 题后必然改档」。**「可以重判」
   描述的是系统**有资格看一眼**了，不是「必须得出一个新档位」。
3. **`null` 是一次诚实的「证据不够」，不是失败。** 这正是 D2 里 `attempted` 双分支
   要区分的事：**没有证据**和**有证据指向中间**是两回事，不能都渲染成同一个状态。
   把 `null` 硬算成一个数字，等于把这两种情况合并。

**真正需要修的从来不是判据，是反馈缺失**：第一版 `explanation` 只说了「暂时算不出
平均首轮正确率」，没说「那要等到什么时候」，于是「答够 5 题却一动不动」看起来就是
重判坏了。现在 `explainRejudge()` 在 `rate === null` 时整句重写为：

> 你在上次定级后又答了 N 题，但暂时算不出平均首轮正确率：重判需要至少一个知识点
> 达到「已熟练」（要 8 题 + 3 种变式），目前还没有。在那之前档位保持不动。

并且**不再拼接「这个表现与 P2 相符」** —— 没有样本就没有「表现」，那句话在
`rate === null` 时是第二句假话。`placement.controller.test.ts` 的「答满 5 题…」
用例逐句断言这几段文案存在，另有阴性对照 `not.toContain('这个表现与')`。
