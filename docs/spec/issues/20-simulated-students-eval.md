# 20: 三档学生智能体与全流程仿真评估

**What to build:** 三个模拟学习者（零基础／有电子学基础／有工程经验）驱动真实浏览器，把应用从头到尾用一遍，输出一份能定位问题的体验报告。

**这一票是「应用可用」的验收关卡**：它跑通，才说明前面所有票拼起来是一个完整应用而不是一堆零件。

**Blocked by:** 03, 06, 07, 11, 12, 13, 14, 15, 16, 18, 19

**Status:** ready-for-agent

- [ ] 三个 persona 在五要素上有实质差异（已有知识清单／知识边界／典型误解／追问容忍度与求助倾向／语言习惯），且通过区分度自检：首轮输入长度、追问容忍轮数、术语密度三项差异不得 <20%
- [ ] 三层评测按顺序执行且不可颠倒：确定性断言层（schema／数值／量纲／状态一致性）→ 模拟用户行为层（Playwright 真实点击输入）→ LLM judge（只评主观）
- [ ] 每个 persona 走完整旅程：首次定级 → 进第一关 → 作答 → 看反馈 → 回图谱 → 看掌握度变化 → 触发一次复验 → 从看板被推荐 → 用一次 skill 库页
- [ ] 报告是 persona × 阶段漏斗矩阵，能竖看「产品问题」横看「适配问题」；每条发现定位到具体界面位置
- [ ] 报告首页标注 `证据等级：假设生成`；`judge_scores.agreement_with_human_kappa` 恒为 `null`（未做 50–100 条人工校准前不得填数）
- [ ] 禁止空泛夸奖：每条评估必须指向可观测事实（点击了几次、在哪一步停下、输入框被清空几次）
- [ ] **不宣称可用性达标**——只输出缺陷与假设，措辞在测试里被断言检查
- [ ] persona 的「典型误解」明确标注为设计假设、未经文献支撑，报告里同样标注
