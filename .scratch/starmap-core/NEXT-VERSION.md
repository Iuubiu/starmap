## 1. 本版本对英文教材做了什么

27 本书里 13 本是英文原版。判据是可复算的一条：`content/<id>/toc.json` 的节点带
ASCII `nameOriginal`，中文书没有。按这条判据各自数出来的数量是 13 / 14，与人工清单
一一对上（`app.sources.lang` 见迁移 `apps/api/migrations/0062_sources_lang.sql`）。

| 动作 | 结果 |
|---|---|
| `sources.lang` 标注 | 14 本 `zh` / 13 本 `en` / 101 篇 `paper` |
| `sources.enabled = false`（13 本英文书） | 保留 `sources` 行留痕，不再出现在任何界面 |
| 级联删除这 13 本的知识点与切片 | `knowledge_points` 7227 → **4030**，`chunks` 96729 → **78204** |
| 删除随之变空的 `modules` | 191 个空壳（362 → **171**） |
| `content/stats` 只列 `enabled` 来源 | 来源表从 128 行降到 115 行（14 书 + 101 论文） |

被停用的 13 本（`sources.id`）：

`content/<id>/` 下的产物（`toc.json` / `chunks.jsonl` / `edges.json`）**没有删除**，
恢复不需要重新解析 PDF，也不需要重跑 OCR。

### 恢复方式

```bash
# 1) 重新启用来源
psql "$DATABASE_URL" -c "UPDATE app.sources SET enabled = true WHERE lang = 'en';"

# 2) 逐本重新入库（走的是同一条生产管线）
pnpm --filter @starmap/api content:import --dir content/knoll-4e-2010
```

`import-content.ts` 现在有一道守卫：来源存在且 `enabled = false` 时**拒绝导入**，
除非显式加 `--force`。理由写在函数注释里 —— 停用书的产物还在磁盘上，任何批量重跑
（比如 `for d in content/*/`）都会把它们静默导回界面，而「移除」这件事没有任何地方
会报警。恢复时先 `UPDATE ... enabled = true` 就不必用 `--force`。

## 2. 推迟到下版本的具体缺陷

### 2.1 答案块误标：英文书 50.7%，中文书 14.3%（原 t46）

**根因（已定位到函数级，未修）**：`tools/ingest/classify.py` 判定「一个 chunk 是不是
答案块」时用 `MAX_FORMULA_PUNCT` 数标点密度。那个判据只数全角标点（`，。；：`），
英文散文的 `.` `,` `;` `:` 全部绕过 —— 于是英文书里成段的正文被判成公式块，再被
「公式块即答案候选」的规则连带标成答案块。

**验收判据（下版本修的时候照这个测）**：修完之后英文书的答案块占比应接近中文书的
14.3% 量级，且 `wrong_on_paper`（答案块指向的页码落在正文区）必须为 0。

**注意**：t46 在 attempt 3 一度把判据加进 `tools/ingest/`，随后按本裁定回退。若下版本
重做，先查 `git log -- tools/ingest/classify.py` 有没有残留提交。

### 2.2 译名三类缺陷（原 t45，**改动已在库里但未经评审**）

content-dev 已交付并自称修完，但独立评审席位（t54）被本裁定取消，所以这批改动**没有
经过第三方验证**，下版本必须先审再信。它声称的数字：

| 缺陷 | 改前 | 改后（严格口径） |
|---|---|---|
| A 不同原文压成同一中文名 | 53 组 / 145 节点 | 0 组 / 0 节点 |
| B 名字里嵌分节编号 | 467 | 55（全是中文原题自带的编号，译文嵌编号 0） |
| C OCR 把小节标题劈成两半 | 2 处 | 已合并（王经瑾，8 张引用表零残留） |

**口径陷阱**（content-dev 自己写在票面）：缺陷 A 必须用严格口径
（剥分节编号含 `A.8` / `B.2` / `1.6.E` 字母段 + 去冠词 + 小写 + 去空白）才得到 0 组；
宽松口径（只剥 `^\d+(\.\d+)+ `）永远剩 9–11 组，那些是同一英文标题的大小写/连字符/
单复数差异，属真同义。下版本复测看到非 0 不要误判为回归。

### 2.3 目录折行标题被拆成两个节点（原 t50，**影响中文书，未推迟**）

票面例子「作用与地位」是中文书的节点，所以这一条**没有**跟着英文书一起推迟，仍在
本版本范围内（见 t50）。写在这里只是提醒：修它的时候会同时改善英文书，但不要因为它
列在「英文教材」上下文里就一并砍掉。

## 12. 架构迁移：把功能从硬编码下沉到 agent + skill（用户 2026-10-22 明确要求）

**用户原话**：「项目的大部分功能要通过 agent + skill 实现」。

**现状**：只有两个动作真由技能驱动 —— `question-author`（出题与校验）、`socratic-tutor`（追问）。其余判定全在代码里：定级 `packages/engine/src/placement.ts` 三档后验、推荐 `recommend.service.ts` SQL 排序、检索 BM25 + 谓词门控、排期 `review.ts` 固定 1/3/7/21/60 天、门控 `GATE_RULES` 常量。模型只负责措辞。

**要做的三件事**：
1. 给模型一个 `skill` 工具，允许它主动加载/切换技能（现在由服务端按回合类型选一个塞进 system message）。
2. 提供一组只读工具：`getLearnerState` / `searchChunks` / `getPrerequisites` / `recordAttempt`（现在是控制器里的 SQL）。
3. 把判定（门控、定级、排期）从引擎常量挪进技能。

**风险（必须先写评估再动手）**：可测性下降（同一学生两次可能得到不同判定）、成本上升（每回合多几次工具调用）、判定不再确定（门控与解锁会变成概率行为）。

**验收前置**：先建一张「判定一致性」评估 —— 同一输入重复 20 次，判定结果的一致率必须 ≥ 95%，否则不许把门控挪出代码。

### 13.1 t82 语义检索已完成（2026-10-23），但有一个规模前提

原表里 t82 标 failed 是因为网关连续 502/403，非代码问题。现已跑通并验收，交付记录见
`.scratch/starmap-core/issues/t82-semantic-retrieval.md`。

**现在为什么够用**：

- 78,204 条 chunk 全量索引，`bge-m3` 1024 维，构建 48 分钟（2900 s，单条约 39 ms）。
- 查询 p50 **35 ms**、p95 206 ms（`topK: 50`，带 DiskANN 索引）；嵌入 p50 23 ms。
  合计 p50 59 ms，在单回合预算里可忽略。
- `chunks.db` **1916.9 MB**（向量 302 MB + 索引 shadow 1.54 GB），本机生成、`.gitignore` 挡住不入库。

**什么时候不够用**：

- **千万切片级**（现在是 7.8 万，差两个数量级）应换成独立向量服务（Qdrant / Milvus 之类）。
  判据不是「数据变多」，而是**索引文件超过可用内存**：libSQL 的 DiskANN 索引走 mmap，
  文件一旦大于内存，p95 会从百毫秒级跳到秒级，那时嵌入式方案的简单性就不再是净收益。
- 现在**没有选** Qdrant 的理由写在这里，避免下一个人重新论证一遍：pgvector 在本机
  PG18 装不上（`pg_available_extensions` 只有 `cube`，上限 100 维 < 1024）；Qdrant 需要
  Docker 常驻，容器链路在本机反复不可用；libSQL 是嵌入式文件库，零外部依赖。
  **没有 Qdrant 在跑是正确状态**，`curl 127.0.0.1:6333` 返回 `000` 不是缺陷。
- **语义只重排、不召回**：BM25 零命中时向量不补位。要让向量也参与召回是另一张票。

## 14. 应用功能清单（本版已具备 / 下版本待做）

记号：**✅ 已实现并有测试或实测**｜**◐ 部分实现**｜**☐ 下版本**

### 14.1 学习主流程

- ✅ **一句话开场**：学习者说「我想学 X」或「我卡在哪」，系统落成一轮学习；不需要先选教材、选章节。
- ✅ **意图确认**：先问两三问（学过没有 / 为了考试还是为了懂 / 手边有什么），把答案写成这一关的判定依据；意图不清不往下走。
- ✅ **三档策略**：P1 给完整例题、P2 留最后一步、P3 直接进判定题；同一知识点、同一套判据，只改起点与节奏。
- ✅ **关卡七段**：引导 → 展示细节 → 简单问题 → 深究 → 进一步讲解 → 判定 → 小结；讲解段与判定段分离，只有判定段算数。
- ✅ **苏格拉底式追问**：不代做，一次一问、不超过两层；不会 / 看不懂先分因，两层无进展就降一层。
- ✅ **逐字流**：`POST /api/v1/agent/turns/stream`，SSE 四类帧（`stage` / `token` / `done` / `error`），前端边收边渲染。
- ✅ **决策链落库**：`agent_turns.trace` 记录注入的技能、检索命中与门控、档位判定、模型与耗时；界面可展开查看。
- ✅ **问津（澄清卡）**：意图不明时给 2–4 个可点选项，点一下即作答，不必打字。

### 14.2 掌握度与判定

- ✅ **双字段掌握度**：`achieved`（历史最高，用于解锁，不下降）与 `current`（当前熟练度，会随时间回落），解决「学过」与「现在还熟」混为一谈。
- ✅ **三条门槛**：作答 ≥8 题、覆盖 ≥3 个变式、连对 ≥2；三条都满足才判达标，不看单一正确率。
- ✅ **出口门控用二项下界**：不是「答对 7/8 就算过」，而是对真实正确率取单侧下界；题量变大时门槛自动抬高。
- ✅ **错题必进复验队列**：答错不影响解锁，但一定回来复验。
- ✅ **复验间隔**：1/3/7/21/60 天阶梯；答错只下调 `current`，`achieved` 不动。
- ◐ **变式去重**：同一变式组只算一次；跨来源（教材 / AI 生成 / 自制）的变式合并规则仍偏粗。

### 14.3 知识图谱与检索

- ✅ **图谱导航**：默认只展开当前知识点两跳以内的网络；节点按掌握状态着色与区分形状，点击进入关卡。
- ✅ **检索门控**：检索命中后按分数门控放行（阈值 0.4/0.7），低分片段不进上下文。
- ✅ **答案附录隔离**：教材答案页被标记为 `is_answer_key`，**永不进检索**，防止把答案喂给模型。
- ✅ **来源可追溯**：每个知识点、每条切片都能回到「哪本书、第几页、页码范围」。
- ✅ **语义重排**：libSQL 内嵌向量库做重排（BGE-M3 1024 维）；**只重排、不召回**。
- ☐ **向量参与召回**：BM25 零命中时用向量补位。
- ☐ **按名字在地图上找点**：目前只能在右栏列表里滚。

### 14.4 关卡与内容

- ✅ **七段模板生成关卡**：选模板、选知识点、选节奏档位 → 预览 → 保存。
- ✅ **AI 批量出题**：按知识点批量生成，产物过与自制关卡同一个校验器；过不了的入库失败但不拖垮整批。
- ✅ **题目池分离**：AI 生成的题只进练习池（`pool: practice`），要进判定池必须有人把 `meta.author` 改成 teacher/self。
- ✅ **关卡市场**：预制关卡 + 自制关卡，可导出/导入 `.level.json`。
- ✅ **内容库四分类**：教材 / 期刊 / 题库 / 技能分开验收，每类空态写明「没有」还是「没加载」。
- ✅ **27 本教材入图**（中文 14 启用 + 英文 13 停用）、101 篇论文零 OCR 入图。
- ◐ **英文教材质量**：译名塌缩、答案块误标两类问题整体推迟，见第 2 节。

### 14.5 应用外壳与交互

- ✅ **三栏**：左图标导航 + 会话列表、中内容列、右个人看板；非聊天页收起会话列，中栏占满。
- ✅ **右栏个人看板**：学科进度、现在该学哪一课、复验与诊断、当前档位、本知识点进度、实时建议、这一会话 —— 全部读真接口，取不到显示「—」并说明原因。
- ✅ **建议可点即用**：右栏每条建议点一下就把这句话填进输入框并发出去。
- ✅ **浅色 / 深色双主题**：语义 token 一套、两种取值；首帧不闪。
- ☐ **左栏折叠**：聊天页还不能把会话列表收起。
- ☐ **技能详情抽屉**：产品 `/skills` 页目前只有列表，看不到技能正文与最近调用。
- ☐ **地图按名检索**、**按章节批量建关卡**。

### 14.6 可观测性与工程约束

- ✅ **OpenAPI 为唯一真源**：契约生成前端类型与客户端，`contract:check` 纳入门禁（当前 58 条 path / 122 个组件）。
- ✅ **全仓门禁**：类型检查、依赖边界、契约同步、迁移可回滚、单测、内容管线、端到端 smoke 七段。
- ✅ **单用户本地部署**：PostgreSQL + 本地文件，无账号体系，不需要登录。
- ☐ **多用户**：当前设计明确不支持，若要多用户需重做鉴权与数据隔离。
