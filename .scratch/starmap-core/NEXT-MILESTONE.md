## M1 向量参与召回（当前只重排）

- **现状**：libSQL 内嵌向量库对 BM25 结果做重排；BM25 零命中时向量**不补位**，所以「词对不上但语义相关」的片段永远进不来。
- **动这里**：`apps/api/src/retrieval/`（检索编排）、`content/embeddings/chunks.db`（索引产物）、可能新增一条迁移记录索引版本。
- **判据**：
  1. 构造 5 条「中文问法 / 教材英文术语」的查询，BM25 全零命中时向量能召回 ≥1 条相关片段；
  2. 原有 30 条检索回归用例（`packages/engine` + `apps/api` 里的 retrieval 测试）全部不变绿；
  3. 检索 p95 增幅 < 80ms（先量基线，别拍脑袋）。
- **坑**：向量补位会打开「召回噪声」的口子，**必须先过检索门控（0.4/0.7）**再进上下文；答案附录（`is_answer_key`）仍然绝对不能进。

## M2 地图按名字找点

- **现状**：`apps/web/src/pages/MapPage.tsx` 只能靠右栏列表滚动或点节点；知道名字但不知道在哪，就找不到。
- **动这里**：`MapPage.tsx`（加搜索框）、`apps/web/src/graph/`（名称索引与命中高亮），复用现成的 `visibleSubgraph()` 做定位。
- **判据**：
  1. 输入「吸收律」能定位到对应节点并高亮，视野自动收到该点两跳；
  2. 搜索 200ms 内出结果（本地索引，不发请求）；
  3. 空结果是「没找到这个知识点」而不是空白面板。
- **坑**：3077 个节点里有大量重名（`信号`、`小结`），结果必须**带来源书名消歧**，否则列表里出现 10 个一模一样的名字。

## M3 左栏折叠

- **现状**：聊天页的三栏固定；会话列表 15% 宽，想专心看内容时收不起来。
- **动这里**：`apps/web/src/v2/V2Shell.tsx`（状态与持久化）、`apps/web/src/v2/v2.css`（`.v2-sessions` 与网格）。
- **判据**：
  1. 折叠后中栏宽度按比例变大（15% → 0，中栏吃满），**输入条位置不动**（底部间距仍是 11px）；
  2. 状态存 `localStorage`，刷新后保持；
  3. 折叠/展开带过渡，不做瞬间跳变；
  4. 非聊天页行为不变（本来就是隐藏会话列）。
- **坑**：网格是 `64px minmax(180px,15%) minmax(0,50%) minmax(300px,35%)`，直接删一列会让 `grid-column` 全错位，要用 class 切换模板而不是移除元素。

## M4 技能详情抽屉

- **现状**：`apps/web/src/pages/SkillsPage.tsx` 只有卡片列表；正文（SKILL.md）与最近调用看不到。演示版里已经有这个交互，可作为视觉参考。
- **动这里**：`SkillsPage.tsx`（抽屉）、`apps/api/src/`（新增 `GET /api/v1/agent/skills/:id` 返回正文 + 最近调用计数）、`packages/api-contract`（先写契约，再生成客户端）。
- **判据**：
  1. 点卡片出抽屉，含：简介、触发场景、正文全文、最近 3 次调用（时间 + 知识点 + 结果）；
  2. 禁用技能不返回正文（避免「看起来能用」）；
  3. 契约先行：`openapi.yaml` 里能看到这个 path 与 schema。
- **坑**：技能正文来自 `apps/api/src/mastra/skills/` 目录，**扫描结果要缓存**，别每次请求都读盘；禁用状态以目录 sidetable 为准，不要在前端过滤。

## M5 变式去重加严

- **现状**：`packages/engine/src/mastery.ts` 里同变式组只算一次，但判定依据是「题目自报的变式号」，跨来源（教材原题 / AI 生成 / 自制）合并规则偏粗，同一道题换个来源会被算成两个变式。
- **动这里**：`packages/engine/src/mastery.ts` 与三条属性测试（`mastery.property.test.ts` / `mastery.replay.test.ts`）。
- **判据**：
  1. 同一题干（归一化后 hash 相同）即使来源不同，只计 1 个变式；
  2. 现有 8 条门槛用例（作答 ≥8 / 变式 ≥3 / 连对 ≥2）行为不变；
  3. 新增一条属性测试：随机生成 100 组「同题不同来源」，去重后变式数恒为 1。
- **坑**：归一化会误伤——`Y = A + A·B` 与 `Y = A + AB` 是同一题，`A·B` 与 `A+B` 不是。**先写一个题干归一化的纯函数并测它**，别把逻辑塞进计数里。

## M6 英文教材质量恢复（体量最大）

- **现状**：13 本英文教材已入库但 `sources.enabled = false`，节点已从图谱移除；缺陷细节见 `NEXT-VERSION.md` 第 2 节（答案块误标 50.7%、译名塌缩 53 组、467 个名字里嵌编号、2 处 OCR 把标题劈两半）。
- **动这里**：`tools/ingest/translate.py`（译名兜底与塌缩）、`tools/ingest/fix_answer_key.py`（答案附录判据）、导入脚本；**不要动 `tools/ingest/toc.py` 的既有判据**（12 本中文书依赖它）。
- **判据**：
  1. 同书内译名唯一率 100%（不同原文不得压成同一中文名）；
  2. 节点名不含纯数字编号；
  3. 答案附录识别在 15 本英文书上误标数 = 0，且不误伤正文小节；
  4. 重新启用后跑一次全仓门禁七段全绿。
- **坑**：这一步会改库，**先备份**（`.scratch/backup-*.sql` 有先例）；恢复是「重新启用来源 + 逐本重跑同一条生产管线」，不是手工改数据。

## M7 多用户（需要先做架构决策，别直接开工）

- **现状**：明确不支持。无账号体系、无租户隔离，`app.*` 所有表都没有 `user_id`。
- **动这里**：几乎全部——鉴权、每张表的租户列与索引、行级隔离、迁移、契约、前端登录态。
- **判据**：先出一份 ADR（`docs/adr/`），说清「是否做、做到哪一层隔离（行级 / schema 级 / 库级）」，再谈代码。
- **坑**：这是唯一一条**不建议在下一个对话里实现**的项。它会把单用户的所有简化设计推翻（`achieved`/`current` 的全局唯一性、无登录的本地部署假设）。**先拍决策，再谈工期。**

## 每条开工时的固定动作

1. 先跑 `node scripts/verify.mjs`，确认**七段全绿**再动手（6/7 就别开始，否则分不清是谁弄红的）。
2. 只改本条 `动这里` 里列出的文件；越界改动单独开票。
3. 完成判据逐条实测，**把数字写进回执**（不是「已实现」，而是「p95 +42ms，检索 30 条回归全绿」）。
4. 提交信息写清「改了什么 / 为什么 / 怎么验的」。
