# StarMap 演示操作卡

> 一句话：**先演「三种学习者学同一个知识点」（主线，约 6 分钟）**，再用零模型五连
> 证明资产厚度（背景，约 2 分钟）。主线是核心，五连只是铺垫 —— 顺序反过来讲，
> 观众看到的是「一个能查资料的软件」，而不是「会因材施教的老师」。

演示前请先跑「演示前状态自检」（第 3 节），三条命令，30 秒。

---

## 1. 三种学习者学同一个知识点（主线）

### 1.1 为什么这条能立住

三档（P1 / P2 / P3）不是三个主题，而是**同一个知识点、同一句开场话术**下，
系统对「这个人该怎么学」给出的三套不同参数：

| 维度 | P1 小陈（211 零基础） | P2 林（研二有基础） | P3 老周（现场工程师） |
|---|---|---|---|
| `firstRoundShape` 第一轮形态 | `worked_example` 整段讲解摊开 | `completion` 最后一张卡待补全 | `direct` 跳过纯讲解直接出题 |
| `ladder.start` / `cap` 台阶 | 1 / 3 | 2 / 4 | 3 / 5 |
| `feedbackTiming` 反馈时机 | `step_immediate` 逐题即时 | `step_immediate_with_summary` 逐题即时 + 关末总结 | `item_deferred_with_summary` 整段提交后统一给 |
| `attemptsPerItem` 每题机会 | 2 | 2 | 1 |
| `masteryRule.consecutiveCorrect` 连对判定 | 2 | 2 | 1 |
| `sessionNewKpLimit` 一次推进 | 2 | 3 | 4 |

六维里**任意两档至少 4 维不同**（脚本里的硬断言），实测：

| 比较 | 不同的维数 | 备注 |
|---|---|---|
| P1 vs P2 | **4** | 最紧的一组：`attemptsPerItem`（2/2）与 `consecutiveCorrect`（2/2）相同 |
| P1 vs P3 | 6 | 全不同 |
| P2 vs P3 | 6 | 全不同 |

P1 与 P2 在「给几次机会、连对几次算掌握」上**是一致的**，放宽到 1 次机会的是 P3 ——
如果只比 P1 vs P3，这一点会被完全掩盖。这也是硬断言要求「两两比较」的原因。

真值全部来自 `GET /api/v1/tier`，不是从界面文案反推的 —— 文案是给观众看的，
参数是给断言用的，两者混过一次就会写出「看起来对但没断言」的测试。

三段共用的输入（`zz-demo-tiers.spec.ts:40` 的常量，改一处三段一起变）：

- 开场话术：`我想学布尔代数的基本运算`
- 知识点：`kp-bool`（布尔代数基本运算）
- 关卡：`lv-bool-laws`（逻辑代数基本律：吸收律与德摩根律，4 题 / 14 分钟）

### 1.2 每段的 4 句话术（照着念，括号里是「让观众看到什么」）

#### 第 1 段 · P1 小陈：零基础

> ①「这是我们的一位 211 大三学生，布尔代数第一次学。」
> （定位观众：不是专家，接下来所有的"慢"都是给他设计的。）
>
> ②「他说一句『我想学布尔代数的基本运算』——注意，他**没有**说自己是零基础。」
> （强调系统不靠用户自报档位，档位是定级或学习历史算出来的。）
>
> ③「同一句话，P1 档给他的是一张**整段讲解全摊开**的关卡：第 1 段就把
> 『为什么数字电路里要反复化简逻辑式』从头讲到尾，一道题都没有。」
> （指着关卡页第一条要点「讲解全展开」与整段正文 —— 这就是"讲透再练"。）
>
> ④「每题给他 2 次机会，连对 2 次才算掌握，一次最多推进 2 个新知识点。」
> （指着卡片四格里的**第 4 格「难度档 P1」**，再指右栏「本次会话新知识点」
> 下面那行「按 P1 档，一次最多推进 2 个新知识点」。）

**用手指标的一处差别**：进关卡后第一屏，标题下方第一条要点写着
**「讲解全展开」**（约屏幕 390,155），正文是一整段 300 余字的讲解、DOM 里
`<details>` 数量为 **0** —— 没有任何内容被折叠。

#### 第 2 段 · P2 林：研二，有基础

> ①「换成研二的林同学，同一句话，同一个知识点。」
> （强调"同"字：差异只能来自档位。）
>
> ②「P2 档不再把讲解直接摊开 —— 同一段、同一个标题，但**正文被折进卡片里**，
> 只给标题，让他先自己推，推完再点开对答案。」
> （指着那张灰卡：「为什么数字电路里要反复化简逻辑式」+ 红字「正文已收起」，
> 下面一行「这一步留给你补：点开看讲解」。）
>
> ③「反馈也从『逐题即时』变成『逐题即时 + 关末总结』，一次能推进 3 个知识点。」
> （指着「按 P2 档，一次最多推进 3 个新知识点」。）

**用手指标的一处差别**：关卡页第一屏那张**灰底卡片**
（约屏幕 350–1165, 365–500）：标题在、正文被收进 `<details>`，红字写
**「正文已收起」**、下面一行「这一步留给你补：点开看讲解」。DOM 里恰好
**1 个** `<details>`，且 `details[open]` 为 **0** —— 默认关着，不是没写。

#### 第 3 段 · P3 老周：现场工程师

> ①「老周在探测器现场干了十年，他不需要有人给他讲什么是与或非。」
> ②「同一句话，P3 档**直接跳过前两段纯讲解**，一进关卡就停在第 3 段·简单问题，
> 第一屏就是一道题。」
> （指着段导航条：1、2 段已经是 ✓，第 3 格高亮。）
>
> ③「每题只有 1 次机会，连对 1 次就算掌握，整段提交后统一给反馈。」
> （指着「每题只有 1 次机会」与「整段提交后统一给反馈」。）
>
> ④「三档看到的**是同一张关卡、同一批题**，差别全在『先讲还是先练、讲多少、
> 给几次机会』—— 这就是因材施教落到参数上的样子。」
> （收束：把观众注意力从"三个不同页面"拉回"一套内容的三种讲法"。）

**用手指标的一处差别**：关卡页标题右侧徽标
**「按 P3 档渲染」**（约屏幕 1017,75）＋段导航条**第 3 格**高亮（约 573,274），
首屏直接是「第 3 段 · 简单问题」的判定题「下列哪一个式子恒等于 A？」。

### 1.3 三段顺序与切档命令（原文）

**必须逐档串行**：切档 → 演完 → 再切下一档。

```bash
# 第 1 段
node .scratch/demo-set-tier.mjs P1

# 第 2 段
node .scratch/demo-set-tier.mjs P2

# 第 3 段
node .scratch/demo-set-tier.mjs P3
```

脚本一次事务改三列：`tier` / `status='provisional'` /
`attempts_baseline=<当前计入掌握度的作答数>`。

**只改 `tier` 不够**：看板一打开就会触发「够 5 题就重判」，档位会被立刻算回去 ——
这是这个脚本存在的原因，也是「不要手改数据库」的原因。

### 1.4 为什么三段不能同时开三个标签页

档位存在 `app.placement_profile` 里，**全站共享一行**（单人单机的本地部署）。
三个标签页读到的是同一行，于是三段画面会**完全一样**。

这不是推测：第一版脚本就是这么失败的 —— 两个 context 同时打开，都读到 P1，
六维全部相同，硬断言「至少 4 维不同」当场变红。

所以演示脚本的写法是：**for 循环逐档 → `execFileSync` 切档 → 新开 context →
取证 → 关掉 context**，全程串行。现场演示同理：一次只开一个窗口。

| 顺序 | 内容 | 时长 | 定位 |

|---|---|---|

## 3. 演示前状态自检（三条命令，30 秒）

### ① 三个服务是否都活着

```bash
curl -s -o /dev/null -w "api %{http_code}\n" http://127.0.0.1:3001/api/v1/health
curl -s -o /dev/null -w "web %{http_code}\n" http://localhost:5173/
node .scratch/demo-data-check.mjs    # 这条同时验证 PG 连得上（它要查库）
```

期望：`api 200` / `web 200` / 数据报告有数字。任一不是 200 就不要开始 ——
三档主线的首屏要等 `/agent/turns` 返回，接口挂了会停在「正在生成这一轮的卡片…」。

### ② 档位与重判基线是否可改

```bash
node .scratch/demo-set-tier.mjs P1 --dry-run
```

期望输出形如（**真实运行记录**）：

```
改前：tier=P3 status=provisional attempts_baseline=59
本轮计入掌握度的作答数：60
[dry-run] 将改为 tier=P1 status=provisional attempts_baseline=60（未执行）
```

`--dry-run` 只读不改。看到「改前」与「将改为」两行都在，就说明库连得上、
`attempts_baseline` 会被一起刷新（少了这一列，档位一打开看板就会被重判回去）。

### ③ 学习数据是否干净（只报告，不删）

```bash
node .scratch/demo-data-check.mjs
```

真实输出（2026-10-22 21:07 跑的一次；数字会随每次演示/测试上涨，读法看下面）：

```
agent_turns | 467
attempts | 99
attempts@kp-bool | 99
learning_log | 24
mastery | 1
mastery@kp-bool | 1
node_unlocks | 0
probe_sessions | 217
```

**这个数怎么读**：`kp-bool` 上有 99 条作答，所以三档主线的首屏文案会是
「你已经达到掌握状态 / 掌握度已经是满分状态」而不是「还没学过」。

两种处理，演示前选一个：

- **A（推荐，零风险）**：换一个未学的知识点演（从知识地图里挑一个标 `未学` 的，
  或改 `zz-demo-tiers.spec.ts` 的 `KP` 常量）。首屏会变成「你还没学过 X，先从这里开始」。
- **B**：清学习数据。**脚本不替你清** —— 这是共享库，别的泳道正在往里写
  （t43/t64 期间真实发生过 `attempts` 从 58 涨到 59）。要清请人工决定、人工执行。

## 4. 一键复现（自动化版本）

```bash
# 三档主线：切档 + 两次截图 + 六维真值 + 硬断言，产出 .scratch/demo/tiers.json
cd apps/web && npx playwright test --config=../../.scratch/qa/playwright.config.ts demo \

cd apps/web && npx playwright test --config=../../.scratch/qa/playwright.config.ts zz-demo-tiers \
  --output=../../.scratch/pw-demo-tiers
```

产物：

| 文件 | 内容 |
|---|---|

| `.scratch/demo/tier-P1-level.png` … `tier-P3-level.png` | 三档进关卡后的第一屏 |

默认通道 median **4.2–6.4 秒**、最坏一次 36 秒。所以演示**必须**用

## 5. 出问题时的三句话

| 现象 | 最可能的原因 | 现场怎么办 |
|---|---|---|
| 三档画面一模一样 | 没切档 / 三个标签页同时开着 | 关掉多余标签页，重跑 `demo-set-tier.mjs <档位>` |
| 首屏一直「正在生成这一轮的卡片…」 | `/api/v1/agent/turns` 挂了或没起 `DEMO_LLM=1` | 跑自检①，重起服务；或改讲零模型五连（第 2 节） |
| 首屏写「模型暂时不可用」+ 一串问题编号 | 上游模型这一次没返回（默认通道实测偶发，一次要等满 45s 超时才回这张卡） | 点卡片下方「再试一次」——它重发的是**同一句话**，不是新的一轮；通常第二次就出来了 |
| 首屏写「你已经掌握」 | `kp-bool` 上有历史作答（见自检③） | 提前换未学知识点，别现场解释 |

**关于「模型暂时不可用」**：默认通道实测偶发（同一句话连打 6 次：4 次 2–8 秒正常、
2 次各卡满 45 秒才回这张卡）。现场就点卡片下方的「再试一次」，它重发的是**同一句话**，
不是新的一轮，通常第二次就出来了。

`zz-demo-tiers.spec.ts` 走等价路径（重新填一次输入框 + 点「提交这一轮」，因为错误卡上
那个按钮点下去会立刻被「正在生成」的骨架替换掉，Playwright 会一直重试到超时），
每档最多重发 3 次；3 次都失败才判红 —— 那时演示本身也跑不下去了，红是对的信号。
**它没有放宽任何档位断言** —— 六维、首轮形态、三处界面差异的硬断言一条没动。
硬化后连续 3 次 verify 全绿。
